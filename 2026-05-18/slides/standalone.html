Harness Engineering

AI가 만든 결과를 사람이 매번 손으로 검증하는 대신, 팀의 자동 검증 기준을 통과하게 만드는 일입니다.

공개 자료에서 보이는 공통 패턴

에이전트에게 지시만 주는 것이 아니라, 저장소 규칙·훅·CI·리뷰 루프를 함께 제공합니다.

Internal Platform Service Status All systems normal

Internal Platform Service Status All systems normal
Scheduled maintenance API Gateway · 2026-05-20 19:00-20:00 KST

목표 — 첫 화면에 점검 배너

HTML 시연: mini-status-harness

현재 상태 페이지에 예정 점검 배너를 추가해줘.
운영 공지, ops audit log, HTML 결과 리포트까지 업데이트하고
완료 전 npm run maintenance:complete를 실행해줘.
베이스라인요청변경체크포인트완료 게이트화면리포트

시연 전: 베이스라인 HTML

시작점은 점검 배너가 없는 정상 상태 페이지입니다.

시연 1: 요청

LLM input
현재 상태 페이지에 예정 점검 배너를 추가해줘.

조건:
- 점검 시간은 2026-05-20 19:00-20:00 KST
- 영향 서비스는 API Gateway
- 사용자가 첫 화면에서 바로 볼 수 있어야 함
- 운영 공지 문구도 함께 업데이트해줘
- ops audit log도 남겨줘
- 결과 리포트에 통과한 하네스 목록, 로그, 화면 snapshot 근거도 포함해줘

작업 방식:
- AGENTS.md의 레이어별 checkpoint 규칙을 따라줘.
- 완료 전 반드시 npm run maintenance:complete를 실행해줘.
- maintenance:complete가 통과하기 전에는 완료 보고하지 마.
사람은 원하는 운영 상태와 완료 게이트를 요청하고, 세부 검증은 프로젝트 규칙에 맡깁니다.

시연 2: AI 변경

configmaintenance.enabled, 일정, 영향 서비스
UI배너 DOM, 렌더러, 토큰 기반 스타일
ops운영 공지, changelog, audit log
evidence하네스 로그, snapshot, HTML 리포트
변경은 한 파일이 아니라 config, UI, design, docs, ops, evidence까지 이어집니다.

시연 3: 레이어별 체크포인트

> npm run test:config
config check passed

> npm run test:ui
ui smoke check passed

> npm run test:design
design contract check passed

> npm run test:ops-log
ops log check passed
Codex는 구현 중간에 레이어별 checkpoint를 실행하며 완료 조건을 확인합니다.

시연 4: 최종 완료 게이트

> npm run maintenance:complete

lint passed
unit tests passed
config check passed
api contract check passed
ui smoke check passed
docs check passed
design contract check passed
ops log check passed
report check passed
완료 보고는 최종 게이트가 통과한 뒤에만 가능합니다.

시연 5: 실패 없이도 남는 증거

Narration
이번에는 Codex가 한 번에 모든 레이어를 맞췄습니다.

중요한 것은 실패가 났느냐가 아니라,
완료 전에 모든 하네스를 통과했다는 증거가 남는다는 점입니다.
시연의 결론은 실패 장면이 아니라 검증 가능한 완료 증거입니다.

시연 6: 화면 확인

첫 화면에서 API Gateway 예정 점검 배너가 바로 보입니다.

시연 7: HTML 결과 리포트

마지막 산출물은 코드가 아니라, 요청·검증·화면 증거가 묶인 HTML 리포트입니다.

Harness가 천장을 받친다

"Vibe Coding이 바닥을 올린다면, Agentic Engineering은 천장을 높인다."— Andrej Karpathy

천장은 저절로 올라가지 않습니다. AI가 더 많이 만들수록 검증·운영 부담이 같이 늘어나기 때문입니다. Harness Engineering은 그 부담을 조직이 감당할 수 있게 만들어, Agentic Engineering의 천장을 실제로 도달 가능하게 합니다.

AI가 더 많이 구현할수록

사람은 문제 정의자, 기준 설계자, 예외 판단자에 가까워집니다.

하네스의 위치

AI 변경과 머지/배포 사이에서 빌드·테스트·리뷰·운영 기준을 실행합니다.

사람에게 남는 책임

무엇을 만들지, 어떤 기준을 지킬지, 어떤 예외를 허용할지 결정합니다.
