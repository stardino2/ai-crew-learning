⑤ 프롬프트 기법

품질이 안 나올 때 여기를 보세요. 핵심은 두 가지입니다 — 프롬프트를 AI가 대신 써주게 하거나(메타프롬프트), 막히면 AI가 나에게 거꾸로 물어보게 하는 것입니다.

A메타프롬프트 — 프롬프트 만드는 프롬프트 ⭐

거친 요청을 던지면 AI가 고품질 프롬프트로 다시 써준다. 이거 하나가 평균 프롬프트 품질을 끌어올림.

복붙 
너는 프롬프트 엔지니어다. 아래 내 거친 요청을
실행 가능한 고품질 프롬프트로 다시 써줘.

규칙:
- [목표] [맥락·제약] [원하는 출력형식] 3요소로 구조화
- 모호한 부분은 추측 말고 나에게 되물을 질문 2~3개 먼저
- 군더더기 빼고 토큰 효율적으로

[내 거친 요청]
<여기 한 줄로>
흐름. 메타프롬프트 → AI가 되묻는 질문에 답변 → 완성된 프롬프트 받기 → 그걸로 실제 작업. 한 번 만든 좋은 프롬프트는 재사용하세요.

실제 대화 예시

[나]  너는 프롬프트 엔지니어다. 아래 거친 요청을 고품질
      프롬프트로 다시 써줘. 모호하면 먼저 2~3개 되물어.
      [요청] 우리 페이지 성능 좀 개선하고 싶어.

[AI]  좋습니다. 먼저 확인할게요.
      1) 어떤 지표가 문제인가요? (LCP·FCP·번들크기 등)
      2) 스택은? (React/Vue/순수 JS, 빌드 도구)
      3) 원하는 출력은? (체크리스트 / 코드 diff / 보고서)

[나]  LCP가 느려. React+webpack. 코드 diff로.

[AI]  (완성 프롬프트)
      "React+webpack 앱의 LCP를 개선하려 한다. 측정값 4.2s.
       원인 후보를 영향 큰 순으로 짚고, 각 수정을 diff로,
       번들 변화 예상치 포함. 큰 구조변경은 먼저 물어볼 것."

B막히면 거꾸로 — AI에게 역질문시키기 ⭐

"뭐라고 물어야 할지조차 모르겠다" 싶을 때 씁니다. 프롬프트를 내가 다 쓰지 말고, AI가 나에게 되물으며 같이 구체화하게 만드세요.

복붙 
나는 <하고 싶은 일>을 하려는데 어떻게 요청해야 할지
잘 모르겠어. 바로 답하지 말고, 내 의도·제약·원하는
결과를 좁히는 질문을 한 번에 2~3개씩 나에게 먼저 물어봐.
내가 답하면 그걸 반영해 다음 질문을 해줘. 충분해지면
그때 완성된 프롬프트(또는 결과)를 만들어줘.

[지금 아는 것] <대충 아는 만큼만>
언제 쓰나. 요구가 흐릿할 때 · 도메인이 낯설 때 · 뭘 빠뜨렸는지 모를 때. AI의 역질문이 빠진 맥락을 끌어냅니다.
메타프롬프트(A)와 차이. A는 "거친 요청 → 좋은 프롬프트로 재작성"이고, B는 "요청 자체가 막혔을 때 → 대화로 같이 발굴"입니다. 막히면 B로 윤곽을 잡고, 잡히면 A로 다듬으세요.

C좋은 프롬프트 공식

[목표] + [맥락·제약] + [원하는 출력 형식]
나쁨 ✗좋음 ✓
버그 고쳐줘이 함수가 빈 배열에서 터진다. 원인 짚고 최소 수정만, diff로.
로그 분석해줘이 로그에서 5xx 에러를 빈도순으로 묶고, 근본원인 top3을 근거와 함께.
테스트 짜줘이 함수 테스트. 정상+경계값+실패 케이스, jest로, 각 케이스 이름 명확히.
리팩터해줘동작 유지하며 가독성만 개선. 바뀐 부분·이유 한 줄씩, 큰 구조변경은 먼저 물어봐.

D안티패턴 — 이러면 토큰만 태운다

  • NO"안 돼요"만 던지기. 에러·재현·기대결과 없으면 AI가 추측만 반복.
  • NO통째로 붙여넣기. 관련 부분만. 전체 첨부는 토큰 폭탄.
  • NO바로 "고쳐"라고 시키기. 원인 진단 먼저 → 잘못된 수정 반복 방지.
  • NO모호한 지시. "잘", "적당히", "알아서" → 결과 산으로. 구체적 기준 줘라.
  • NO한 프롬프트에 5가지 요구. 쪼개라. 한 번에 하나.
  • NO출력 형식 안 정하기. "표로/diff로/체크리스트로" 명시하면 재작업 줄어 토큰 절약.
