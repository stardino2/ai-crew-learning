🧩 플러그인 사용

스킬·워크플로우를 묶어 배포하는 패키지입니다. 설치하면 표준 작업 흐름을 슬래시 명령으로 부를 수 있습니다. 각 항목의 설치·사용·예시는 펼쳐서 보세요.

superpowers gstack caveman 설치 전 정책 확인
⚠ 설치 명령·마켓플레이스·허용 플러그인은 버전·조직마다 다릅니다. 아래는 일반 절차이며, 사내 배포 방식이 있으면 그쪽을 따르세요. 외부 플러그인이 코드·데이터에 접근하는 범위를 보고 들이세요(→ ⚠ 안전).

A공통 — 설치·호출 방식

  • 설치 — Claude Code는 마켓플레이스를 등록한 뒤 플러그인을 설치합니다(/plugin 패널). 정확한 절차·허용 마켓플레이스는 사내 안내 우선.
  • GitHub에서 바로 — 공개 GitHub 레포를 마켓플레이스로 등록해 설치할 수 있습니다. 명령으로도, 자연어 프롬프트로도 가능(아래).
  • 호출 — 설치되면 그 안의 스킬을 /스킬이름 으로 부르거나, 상황에 맞을 때 자동 제안됩니다(→ ③ 도구사용법 B).
  • 없는 건 지어내지 말 것 — 설치된 목록에 있는 것만 호출.
플러그인 설치 일반 절차 펼치기
# 1) Claude Code 안에서 마켓플레이스 패널 열기
/plugin

# 2) 마켓플레이스 추가 → 원하는 플러그인 설치 → 재시작
# 사내 배포가 있으면 그 마켓플레이스/절차를 따른다.
# 설치 후 사용 가능한 스킬은 자동 목록에 뜬다.
GitHub 레포에서 설치 (명령)
# 1) GitHub 레포를 마켓플레이스로 등록
/plugin marketplace add owner/repo
#   또는 전체 URL:
/plugin marketplace add https://github.com/owner/repo

# 2) 그 마켓플레이스에서 플러그인 설치
/plugin install 플러그인이름@repo

# 3) 갱신: /plugin marketplace update repo
공개 레포만 됩니다. 사내 배포·허용 마켓플레이스 정책이 있으면 그쪽을 따르세요.
프롬프트로 설치 요청
슬래시 명령을 외우지 않아도, 자연어로 시키면 Claude가 위 /plugin marketplace add 절차를 대신 밟아줍니다. (최종 설치·활성화는 확인창이 뜰 수 있습니다.) 
아래 GitHub 레포를 플러그인 마켓플레이스로 등록하고
거기 있는 <플러그인이름> 설치해줘.
레포: https://github.com/owner/repo
설치 후 사용 가능한 스킬 목록도 보여줘.

Bsuperpowers — 규율 있는 작업 흐름

막 짜지 않게 절차를 강제하는 스킬 묶음 — 브레인스토밍·TDD·체계적 디버깅·계획 작성 등. "바로 코딩 말고 설계·테스트부터"가 필요할 때.

설치
# /plugin 패널에서 superpowers 마켓플레이스 추가 후 설치.
# 공식 저장소(오픈소스) 기준이며 사내 배포가 있으면 그쪽 우선.
사용법
설치되면 상황에 맞는 스킬이 자동 제안되거나 슬래시로 호출됩니다. 기능 만들기 전 브레인스토밍, 구현 전 테스트 먼저(TDD), 버그엔 체계적 디버깅 흐름이 끼어듭니다.
사용 예시
[나] 결제 환불 기능 추가하고 싶어.
[AI] (브레인스토밍 스킬 작동) 먼저 요구를 좁힐게요 —
     1) 부분 환불 허용? 2) 한도·기한? 3) 승인 주체?
     ... 합의 후 → 테스트부터 작성(TDD) → 구현

Cgstack — QA·리뷰·배포 워크플로우

브라우저 QA·코드 리뷰·배포(ship)·계획 리뷰를 묶은 워크플로우. 웹 기능 테스트와 PR 전 점검을 표준화합니다.

설치
# /plugin 패널에서 gstack 마켓플레이스 추가 후 설치.
# 사내 배포가 있으면 그 절차를 따른다.
사용법
슬래시로 워크플로우를 호출합니다. 대표 명령: /qa(사이트 테스트·버그 수정), /review(머지 전 diff 리뷰), /ship(테스트→리뷰→PR), /plan-eng-review(구현 전 계획 리뷰). 정확한 명령은 설치본 목록을 확인하세요.
사용 예시
[나] /plan-eng-review
[AI] (계획 리뷰 스킬) 스코프부터 확인 → 아키텍처·
     테스트·엣지케이스 짚고, 결정마다 추천+이유 제시.

[나] /qa
[AI] (QA 스킬) 사이트 훑어 버그 찾고 → 고치고 →
     재검증 → 전/후 상태 보고.

Dcaveman — 응답 압축 모드

응답에서 군더더기(관사·인사·헤지)를 깎아 토큰을 줄이는 커뮤니케이션 모드. 기술 내용·정확도는 유지. 길게 설명할 필요 없는 반복 작업에 유용합니다.

설치
# /plugin 패널에서 caveman 마켓플레이스 추가 후 설치.
사용법
토글형입니다. /caveman 으로 켜고 강도(lite/full/ultra)를 고르거나, CLAUDE.md/AGENTS.md에 "응답은 간결하게, 결론부터" 규칙을 넣어 상시 적용할 수도 있습니다. 코드·커밋·보안 설명은 자동으로 정상 문장 유지.
사용 예시
[일반] "인증 미들웨어에 버그가 있습니다. 토큰 만료
        검사가 < 대신 <= 를 써야 할 것 같은데..."
[caveman] "Bug 인증 미들웨어. 토큰 만료 검사 < → <=. 수정:"
