01토큰 아끼는 법 — 토큰 부족 환경 1순위

토큰 = 비용. 같은 작업도 컨텍스트 관리에 따라 토큰이 3~5배 차이 난다. 이 장만 지켜도 절반 절약.

핵심 규칙 6개

  • DO한 세션 = 한 작업. 작업 끝나면 /clear. 대화가 길어질수록 매 요청마다 과거 전체를 다시 읽어서 토큰이 눈덩이로 불어난다.
  • NO큰 파일 통째로 읽히지 마라. "이 파일 전체 봐줘" 대신 "login() 함수만 보여줘"처럼 범위를 좁혀라.
  • DO탐색은 위임. "이 기능 어디서 처리돼?"는 서브에이전트(탐색 전용)에 시키면 결론만 돌아온다. 수십 개 파일 덤프를 본문에 안 들인다.
  • DO모델 등급 분리. 오타·포맷·간단 변경은 싼/빠른 모델, 설계·멀티파일 리팩터만 비싼 모델.
  • TIP캐시 5분 룰. 프롬프트 캐시 수명은 약 5분. 작업을 끊지 말고 연속으로. 10분 자리 비우고 돌아오면 캐시 미스 = 전체 재과금.
  • NO같은 파일 반복 읽기 금지. 방금 읽은/수정한 파일을 "확인차" 다시 읽지 마라. 도구가 이미 알고 있다.
체감 예시. 1500줄 파일을 매 질문마다 통째로 첨부 → 질문 10번이면 15,000줄 × 10 재전송. 필요한 함수 40줄만 지정 + /clear 적절히 → 같은 작업 토큰 1/10.

02Claude vs Codex — 택1 기준

개인당 1개만 선택(코덱스/클로드). 우열이 아니라 작업 성격에 맞추는 문제다. 아래 중립 비교표로 본인 업무에 매핑하라.

항목Claude (Claude Code)Codex
강한 영역 여러 파일 걸친 리팩터, 코드베이스 탐색·이해, 운영 스크립트/자동화, 긴 맥락 작업 격리된 단일 함수·알고리즘 구현, 명확히 정의된 문제의 빠른 풀이
작업 단위 "이 시스템 어떻게 동작?" 같은 넓은 작업에 강함 "이 입력 받아 이 출력" 같은 좁고 명확한 작업에 강함
도구·확장 MCP / 서브에이전트 / 플러그인·스킬로 워크플로우 확장 에디터 통합 중심, 인라인 코드 제안
맥락 유지 긴 세션·대규모 컨텍스트 관리에 유리 짧고 집중된 컨텍스트에서 효율

웹 개발자라면

화면·API·DB 여러 파일을 동시에 건드리는 일이 많음 → 멀티파일·탐색에 강한 쪽이 유리. 단, 알고리즘/단일 모듈 구현 비중이 크면 취향대로.

운영 엔지니어라면

로그 분석·셸/IaC 스크립트·장애 분석 등 시스템 작업 폭이 넓음 → 시스템 작업·자동화 범위가 넓은 쪽이 유리.

고르는 법 1줄. "내 작업이 여러 파일에 걸쳐 있고 맥락이 길면 Claude 쪽, 한 함수에 갇힌 명확한 문제가 많으면 Codex 쪽." 둘 다 코드 잘 쓴다 — 핵심은 작업 모양.

03웹 개발자 실전 워크플로우

상황별 행동 순서 + 그대로 쓰는 프롬프트. 6장에 더 많은 템플릿 있음.

버그 수정

  • 증상·에러로그·재현 경로를 먼저 붙여라. "안 돼요"만 던지면 토큰만 쓰고 헛돈다.
  • 고치라고 바로 시키지 말고 원인부터 짚게 하라. 잘못된 수정 반복이 토큰 낭비 1위.
복붙 
다음 에러의 원인을 먼저 진단해줘. 바로 코드 고치지 말고
의심 가는 위치 2~3곳을 file:line 으로 짚어줘.

[에러 메시지]
<여기 붙여넣기>

[재현 방법]
1) ... 2) ...

기능 추가

  • 기존 패턴을 따르게 하라: "이 프로젝트의 기존 컴포넌트와 같은 스타일로".
  • 큰 기능은 한 번에 시키지 말고 작은 단계로 쪼개서.

코드 리뷰 (머지 전)

복붙

칭찬 말고 문제만. 각 항목은 한 줄: 위치 / 문제 / 고칠 방법.

04서버·운영 엔지니어 실전 워크플로우

운영은 사고 한 번이 치명적. "명령 생성"과 "명령 실행"을 분리하는 게 핵심 원칙.

철칙AI에게 운영 서버 직접 명령을 맡기지 마라. 스크립트·명령을 만들게만 하고, 실행은 사람이 검토 후 직접. 특히 prod.

05안전수칙 (필수)

  • NO시크릿 붙이지 마라. API 키·비밀번호·토큰·내부 호스트/IP·고객정보. 프롬프트는 외부로 전송된다. 가린 뒤 붙여라.
  • 확인파괴적 작업은 사람 승인. rm -rf, DROP TABLE, force push, 대량 삭제·덮어쓰기는 실행 전 반드시 검토.
  • 확인prod 변경은 무조건 사람이. AI는 초안·명령 생성까지. 적용 버튼은 사람.
  • NO출력 맹신 금지. 그럴듯해도 틀릴 수 있다. 머지 전 리뷰·테스트 필수.
  • DO회사 정책 우선. 사내 보안·데이터 반출 규정이 이 가이드보다 위. 모르면 보안팀 확인.
