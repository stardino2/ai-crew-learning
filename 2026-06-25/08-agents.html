📄 AGENTS.md 만들기

매 세션 같은 설명을 반복하지 않으려면, 프로젝트 규칙을 파일에 박제하고 도구가 자동으로 읽게 만듭니다. 단일 소스로 관리하는 법을 다룹니다.

규칙 박제 단일 소스 용도별 분할 토큰 절약
⚠ 도구가 어떤 파일명을 읽는지는 버전마다 다릅니다. 개념(규칙을 한 곳에 두고 도구가 그걸 보게 한다)만 가져가고, 실제 파일명·동작은 사내 안내/공식 문서로 확인하세요.

AAGENTS.md를 만든다

AGENTS.md는 여러 AI 코딩 도구가 읽는 공통 관례 파일(plain markdown)입니다. 프로젝트 루트에 두고, "사람이 새 팀원에게 처음 알려줄 것"을 적습니다. Karpathy식 핵심: 빌드·테스트·실행 명령 + 코드 스타일 + 하지 말 것.

# AGENTS.md

## 빌드·실행
- 설치: npm ci
- 테스트: npm test
- 빌드: npm run build
- 로컬 실행: npm run dev

## 코드 스타일
- 기존 컴포넌트 패턴을 따른다
- 새 의존성 추가 전 먼저 물어본다

## 하지 말 것
- prod 배포 명령은 생성만, 실행은 사람이
- 시크릿·고객정보는 코드/로그에 넣지 않는다
왜 AGENTS.md인가. 도구마다 다른 파일(CLAUDE.md·GEMINI.md)에 같은 내용을 복붙하면 갱신이 어긋납니다. 규칙은 AGENTS.md 한 곳에 두고 나머지는 그걸 가리키게 → 단일 소스.

BCLAUDE.md / GEMINI.md가 AGENTS.md를 보게 만든다

Claude Code는 CLAUDE.md, Gemini는 GEMINI.md를 세션마다 자동으로 읽습니다. 이 파일을 얇게 두고 AGENTS.md를 가리키게 하면 중복이 사라집니다.

# CLAUDE.md
먼저 @AGENTS.md 를 읽고 그 규칙을 따른다.
(Claude 전용 보충만 아래에)
- 응답은 간결하게, 결론부터.
# GEMINI.md
프로젝트 규칙은 AGENTS.md 를 기준으로 한다.

@파일 참조는 "그 파일을 지금 읽어라"는 뜻 → ① 빠른시작의 경로 참조와 같은 원리.

C용도별로 쪼개서 "필요할 때만" 읽게 한다

AGENTS.md가 비대해지면 매 세션 통째로 읽혀 토큰을 먹습니다. 루트는 짧은 목차+포인터로 두고, 세부는 별도 파일로 분할 → 도구가 해당 작업 때만 그 파일을 읽습니다.

AGENTS.md            ← 짧게. 아래로 안내만
docs/agents/
  testing.md         ← 테스트 작성 규칙
  deploy.md          ← 배포 절차
  style.md           ← 코드 스타일 상세
# AGENTS.md (루트, 얇게)
- 빌드/테스트: docs/agents/testing.md 참조
- 배포: docs/agents/deploy.md 참조
- 스타일: docs/agents/style.md 참조
💡 효과는 컨텍스트 관리와 동일: 지금 필요한 것만 로드 → 토큰 절약(③ 도구사용법 참조). 배포 안 하는 세션은 deploy.md를 안 읽습니다.
